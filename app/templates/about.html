Sequence Editor {{ app_version }}

Sequence editing, annotation, restriction analysis, cloning simulation and sequencing alignment. It is the general-purpose companion to the MoClo Library Tool: the MoClo tool for a Golden Gate parts library and modular assemblies, and this editor whenever the work is not MoClo based. What it does

Edit and annotate

Type straight into the sequence, with features, colours and translations, as a circular or linear map. GenBank, FASTA and SnapGene files in and out, keeping ApE's colours.

Restriction analysis

What cuts and where, from REBASE: filter by how many times an enzyme cuts, find one that does not cut at all, and draw the digest as a virtual gel.

Cloning simulation

Golden Gate, Gibson, restriction and ligation, and recombination (Gateway LR and BP, loxP, FRT), each giving a product you can save and annotate.

Primers and PCR

Design primers to a melting temperature, simulate the PCR, and see which of the lab\'s own primers bind a sequence.

Sequencing

Align .ab1 chromatograms and FASTA reads to a sequence, with quality, mismatches and coverage, and judge each read. Several reads of one clone are compared against each other, so a bad basecall is told apart from a real mutation. How the alignment works →

Confirming a clone

Confirming a plasmid from its reads makes its glycerol stock in Lab Stocks, so the tube is tied to the sequence that proved it.

With the other tools

  • MoClo Library Tool — shares its library both ways (see below).
  • Lab Stocks — confirming a clone makes its glycerol stock; primers are saved there and read back to show which bind a sequence.
  • Lab Notebook — a plasmid linked with @ in a page opens here.
  • Seed Bank — from a plasmid, the lines made with it, their seeds and plants.

Who sees what

A sequence you save is seen by your own labs. One ticked public is readable by every lab in the suite, which is how a shared backbone is found. Sequencing reads follow the sequence they belong to. Everything is kept on the lab\'s own server and backed up each night with the rest of the suite.

Attribution

The functionality of this tool is modelled on ApE (A Plasmid Editor) by M. Wayne Davis, the desktop program this lab has used for years. ApE is a closed-source Tcl/Tk application, so none of its code is used, bundled or derived from here: the features were re-implemented independently in Python and JavaScript against published algorithms and standard libraries. Where ApE's conventions are useful for interoperability they are followed deliberately — ApE's tab-separated feature-library format is read and written unchanged, and ApE's ApEinfo_fwdcolor / ApEinfo_revcolor GenBank qualifiers are honoured, so files move between the two programs without losing annotations or colours.

If you use this tool in published work, please cite ApE as the origin of the feature set, and note which analyses were run here:

Davis MW, Jorgensen EM (2022). ApE, A Plasmid Editor: A Freely Available DNA Manipulation and Visualization Program. Frontiers in Bioinformatics 2:818619. doi:10.3389/fbinf.2022.818619

ApE itself is available from jorgensen.biology.utah.edu/wayned/ape. This project is not affiliated with or endorsed by its author.

How it fits with the MoClo Library Tool

The two tools run side by side on the same server and share the MoClo databases. Parts, backbones and assembled plasmids from the MoClo tool can be opened here for editing or read alignment.

In the other direction, any sequence in this editor can be ticked as Golden Gate ready. The editor then checks that a single Type IIS enzyme releases exactly one clean insert with two 4 bp fusion sites, and offers to add it to the shared MoClo parts library — stored the way the MoClo tool expects, with both fusion sites included, so it is immediately usable in assemblies there. Sequences that are not Golden Gate compatible stay in this editor only, and the reason they cannot be contributed is reported.

The shared logic lives in a standalone dnakit package inside this repository, so the MoClo tool can adopt it later instead of keeping its own copies of the restriction, translation and export routines.
